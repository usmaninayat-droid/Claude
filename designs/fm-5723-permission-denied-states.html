✓ Recommended pattern

Component spec

One reusable pattern — the same component handles every 403 across the ticketing module.

Primary — Disable + tooltip

When permission is known at render, disable the action and show the reason on hover/focus. Best UX: the wall is visible before it's hit.

Fallback — Toast on 403

API error interceptor pipes any 403 from ticketing endpoints into <PermissionDeniedToast/>. Server supplies the detail line; component supplies the title.

Copy

Title: "Action not allowed"
Body: "You don't have permission to {action}. {server detail}"
Tooltip: "Only the {role} can do this."

Never silent

Every 403 shows exactly one surface — disabled state, toast, banner, or modal. No dead clicks.

Accessibility

role="alert" on toast, aria-disabled on preventive disable so screen readers announce the block. Tooltip reachable via keyboard focus.

Out of scope

Permission logic itself (FM-5677). This ticket is presentation only.
