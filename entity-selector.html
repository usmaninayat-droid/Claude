Cross-module component

One Entity Selector, everywhere you assign something.

Drivers share names. So do assets, and half the vehicles look alike on paper. Every module solves “which one?” its own way today. This is the single, config-driven component that solves it once — search, filter, sort, custom columns, and a preview that actually tells two people apart.

Why this exists

A name is not an identity.

The client flagged it on Smart Planning: three drivers named Arjun Malik and no way to tell them apart at selection time. The fix isn’t “add fields to that one screen” — it’s to make every selector show the fields that disambiguate, and let the user search, filter, and choose which of those fields to see.

Anatomy

Seven parts, assembled from one config.

Each module passes an entity config; the component renders the same anatomy every time. Nobody rebuilds a list.

01 · Trigger

Selected preview

The closed state shows the chosen entity with its identity fields — never just a name. Empty state prompts selection.

02 · Toolbar

Search · Filter · Sort · Columns

Search spans every identity field. Filter opens entity-specific facets. Columns lets the user pick what’s visible — persisted per user, per context.

03 · Bulk bar

Select all · count · clear

Appears only in multi mode. Select-all respects the active filter, so “all” means “all 6 available”, not all 400.

04 · Row

Control · identity · columns · status

Radio (single) or checkbox (multi), avatar + name + primary ID, the toggled columns, and a status pill. Ineligible rows are disabled with a reason.

05 · Preview chips

What’s chosen, disambiguated

Selected items become removable chips carrying the same identity field, so a full selection is auditable at a glance.

06 · Two form factors

Compact ↔ Expanded

A dropdown for quick in-form picks; a panel/table for filtering at scale — same engine, same data, same result. The reports “expand” pattern, standardized.

The “think it through once” bit

Every entity declares the same shape.

Identity fields (always shown), optional columns, a status vocabulary, searchable keys, filter facets, sort keys, and a default mode. Add a new entity by writing this object — not a new screen.

States, defined once

The unhappy paths ship with the component.

Loading

Skeleton rows matched to the configured columns — no layout shift when data lands.

Empty source

No entities exist yet. Prompts the create/import action for that entity, if the user has rights.

No results

Search or filter matched nothing. Offers a one-click “clear filters”. Try searching “zzz” in the demo.

Ineligible

Row visible but not selectable — off-duty, in maintenance — with the reason inline, never a dead click.

Where it lands

Same component, tuned by config.

The only per-module differences are which entity, which mode, and which form factor — all data, no new UI.
