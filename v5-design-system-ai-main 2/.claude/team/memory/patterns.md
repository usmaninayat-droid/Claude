## Fleet/route-ops: live monitoring + plan review (benchmarked Samsara, Onfleet, Routific, OptimoRoute, Locus.sh, Motive — 2026-07-17)

- **Live vs Replay mode**: mode is a top-level SEGMENTED TOGGLE (not a tab), not a filter — Motive uses Fleet View (live, pulsing dot) vs Vehicle/Trip History (static, scrubber + play button, adjustable speed, "replay any trip from past N days"). Onfleet marks on-duty drivers with a live pulsing-circle animation; in-progress leg to next stop = dashed line (vs solid = completed). Pattern: LIVE = pulsing/animated marker + auto-refreshing position; REPLAY = static marker + a scrubber/play-speed control, explicit "as of" timestamp, no pulse.
- **Floating KPI strip over the map**: Onfleet's Command Center "Quick Stats" and Locus Control Tower float route/task/exception counts over the live map (not in a side dashboard) — exact recurring metric set across vendors: on-time %, active/in-transit count, delayed/at-risk count, completed vs total stops, ETA drift. Locus explicitly monitors "deviation and delay risk" continuously and re-optimizes before SLA breach — i.e. delay is framed as a live risk score, not just a lagging stat.
- **Finished vs in-progress day**: in-progress = live counts + "ETA" columns that keep changing + pulsing map markers; finished/historical = the same layout swaps to Planned-vs-Actual (OptimoRoute's own term) — order-by-order comparison of planned time vs actual time, arrival-accuracy chart, no live pulse, static end-of-day summary (Routific: "end-of-day reports").
- **Trip/vehicle progress cards**: universal card anatomy across Onfleet/Samsara/Motive = driver+vehicle id header, stop progress as "N of M stops" (not a raw %), next-stop ETA with a color-coded on-time/late chip, and a delay badge only when at risk — cards live in a sidebar list next to the map, each clickable to re-center the map on that vehicle.
- **Plan review hierarchy (Routific/OptimoRoute)**: the #1 number surfaced before dispatch is stop-plan feasibility, not cost — OptimoRoute's primary post-solve artifact is the "Not Scheduled" tab (which orders got excluded + WHY: time window / capacity / driver availability conflict) shown before the KPI dashboard. Only after unassigned stops are resolved does the analytics view (order status, arrival accuracy, order-type mix) become the review surface. Map shows one color per route + numbered sequence markers as the plan-review default view (matches this app's ROUTE_COLORS pattern).
- **Plan A/B comparison**: NOT a solved, common UI pattern in these vendors (no vendor markets an explicit side-by-side scenario diff) — this is a whitespace/differentiator opportunity, not a "go copy X" pattern. Treat any ScenarioDiff-style feature as original design, not benchmarked.
