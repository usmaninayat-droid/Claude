# Learnings — hard-won lessons (read before acting; append after every loop)

## DS model & laws
- **Never build products inside the DS** — products live in `Code\<slug>\` and consume it via `@ds`. **Default brand = FAMS** (primary blue #0072D6 + logo) unless a custom brand is explicitly requested (theme = tokens + logo only, never baked into a component). Reading big Figma sections times out — fetch frame-level node ids / screenshots.
- **Pipeline model:** progress derives from stage position (`StageProgress`) or an explicit numeric field, never hardcoded. Cards are **type-derived** — a placement picks field+slot, the field TYPE picks the renderer (pill/flag/chip/progress/avatar/date); only `PriorityFlag`/`StageProgress` are named. The dynamic pipeline **detail** is TaskDetail (config-driven tabbed right panel: Timeline/Activity/Linked/Files), not RecordDetail.
- **Filters are multi-facet next to search** — the shell renders ALL `deriveFilters` facets (grouped "All Filters" popover + per-facet dropdowns + chips); the RECIPE decides how many. `filterField`/`getFacet`/`toFilterField` are **NOT dead** — `view-renderers.tsx` still filters rows via `data.filterField.get`; retiring them is a real REFACTOR (migrate onto `facetFilters` first) = T-003, not a delete.

## Token-only / coherence
- The token surface covers every chrome case: white-on-blue nav = `--sidebar-primary`/`-foreground`/`--primary-foreground`; overlays+tints = `color-mix(in srgb, var(--token) X%, transparent)`; status = `--status-*`; dark popover = `--popover`. Only 3 hex categories are legit + take a scoped `// coherence-allow` (with reason): map-engine status→hex bridges, decorative window-chrome, user-selectable colour-DATA palettes (zone/tag). Never blanket-exempt a file. When a ref uses a raw-hex data-viz palette, pass DS tokens (`var(--status-*)`/`var(--chart-N)`) as the colour DATA from the block — component stays token-clean AND coherence green with no allow.
- **Derive-from-colour helpers must handle TOKEN colours, not just hex** (T-015): the kanban rgba() tint helper passed `var(--token)` through at full strength. Fix = hex fast-path + `color-mix(in srgb, color alpha%, transparent)` fallback (works for var()/named/oklch). Audit any alpha-from-colour helper for this blind spot; red-check by seeding a var() colour.
- Coherence gate mechanics: skips inline SVG art, `// coherence-allow` (must be ON the hex line), and COLOR_SOURCE map-* files; a block-comment continuation not starting with `*` trips the scan. Blocks are scanned for CHROME hex only (Tailwind `-[#...]`), not data literals.

## Gates & verification
- Order **coherence → smoke → a11y → roundtrip → vocab → build**. Wire every new gate into a hook/script — a gate only in docs is NOT automation (PostToolUse runs coherence+a11y+roundtrip+vocab per-edit). Always prove a new gate with a **red-check** (seed a violation → confirm FAIL); the first a11y version passed a red-check falsely and exposed a regex bug. When promoting a defect class, prefer the cheapest deterministic scan that catches the actual recurrence over the "ideal" behavioural test — the scan that runs on every edit beats the harness nobody maintains.
- **G-SMOKE** (smoke.mjs): node-env mount-and-assert over config→config-render→config-bridge per golden module (renderer resolves · data binds · surface derives). No jsdom/WebGL. Don't import block/app render trees into node specs (they pull `maplibre-gl` → `window` at import); tsc validates block ModuleConfig shape. **G-A11Y** (a11y-static.mjs): icon-only `<button>/<a>` w/o accessible name · `<img>` w/o alt · positive tabIndex — needs a brace/quote-aware open-tag scan (`[^>]*` breaks on `onClick={()=>…}`); calibrate via comment-skip + `// a11y-allow`.
- **G-ROUNDTRIP** (roundtrip.mjs, T-007) + **G-HYDRATION** (hydration.mjs, T-020) are the drop-on-SAVE / drop-on-LOAD mirror pair over `blocks/**/*.block.tsx`. ROUNDTRIP: every `(d: XxxDraft)=>` save handler must read every top-level Draft field as `d.<field>` OR forward the draft wholesale (`...d`/`[id]: d`); opt out via `// roundtrip-allow`. HYDRATION gates the two clean drop-on-load slices: (A) an edit-path `initial={…drafts[…]}` must carry a `*ToDraftSeed(` fallback (else a seeded row edits BLANK); (B) every `onSaveDraft={h}` must thread a `closeOnDone` discriminator (2-arg upsert; resolves bare-identifier wrappers — else repeated draft-save mints duplicates); opt out via `// hydration-allow`. **BLIND SPOTS neither script catches → review-fix QA checklist:** a seed that silently omits a persisted ROW field (fieldCount→0) or corrupts a COMPOSITE (phone country-code split/join), a `canProceed` step-gate that dead-ends a seeded edit, and POSITIONAL-arg callbacks (`onAssign(id,note,ids)` — gates only scan `(d: Draft)=>`; prefer a single Draft-object arg for anything that persists).
- **G-VOCAB** (vocab.mjs, T-019): shared `app-shell/**` + `navigation/**` chrome must not bake fleet VOCABULARY [Vehicle/Speed/Driver/Fleet/Truck/Depot/Plate] as user-facing UI text — flags V1 JSX text nodes + V2 default-label string literals, but NOT the sanctioned overridable fallback `?? '<word>'` (that IS the fix: `labels?.entity ?? 'Vehicle'`); comments/type-names/blocks/showcase excluded; opt out with `// vocab-allow <word> — <reason>`. KEY design lesson: a vocab gate MUST detect the `?? '<word>'` fallback and exempt it, else it flags the very config-default pattern it's meant to encourage. The domain-MODEL `kind`-branching half stays a review-checklist item.
- **Parity is real** via `scripts/team/parity/shoot.mjs` — local Chrome/Edge headless (puppeteer-core) + software WebGL (`--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`); shoots normal pages AND MapLibre maps (live-preview MCP times out on WebGL). `--click css:/text:/aria:` + `--type "sel::value"` reach nested/field-gated states (watch substring matches — `text:Assign` also hits "Assigned to me"). Use for QA G2 before claiming parity; devDep, never imported by src.

## Blocks first-class
- `blocks/*.block.tsx` export ready ModuleConfigs, import via `@ds/*`, are in tsconfig `include`; compose them into a showcase AppConfig (`smart-cities.config.tsx`) that doubles as the block integration test. tsc surfaces stale icon names — grep `src/icons` for the real PascalCase before use. Embed AppShell in docs by wrapping it (root is `flex h-full w-full`, takes className) and flipping to `fixed inset-0 z-[80]` to maximize.

## The wizard/module data-loss triad (mandatory pattern for every wizard-backed module)
- A `*Sheet` collects a rich Draft; the consumer must persist it faithfully. Three recurring failure classes, each with a fix: **drop-on-save** (forgotten `d.<field>`) → G-ROUNDTRIP + persist wholesale `[id]: d`; **drop-on-load** (seeded row under-hydrates) → `*ToDraftSeed(row)` that reverse-maps the FULL summary incl. composite (phone) + gated (stages) fields, and never destructively recomputes a summary field when the draft carries none; **savedraft-no-closeondone** (repeated draft-save mints duplicates) → `upsert(d, closeOnDone)` that captures the minted id into `editingId` and keeps parent context. Prefer carrying raw ids on the row over reconstructing from display labels.

## Building modules from Figma — durable patterns
- **Extract on the 2nd occurrence** of a UI pattern, don't copy: `StepWizardSheet` (stepped right-sheet: header + clickable step tabs + Back/Proceed + `onCancel`/`secondaryAction`), `SelectableCard` (checkbox option card + expand/`trailing` slots + selected-icon primary tint), `LabeledSelect` (`field-select.tsx`, floating-label popover select + keyboard roving) are the shared shells. Reuse DS primitives (`Badge` tint pill, `Tooltip`, `AlertDialog`) over hand-rolling spans / native `title` — the review panel flags these every time.
- **Multi-surface modules → deliver the entry spine, ticket the rest.** Events/Operations/Contracts are each 4–6 surfaces (list + wizard + detail + dashboard + sheets); build the coherent spine well + parity-verify, defer the big net-new views to a tracked pass rather than half-build them unverified. Config-driven vocab throughout; expose `stats` as an explicit prop when a design's summary row isn't a partition of the visible items; resource-meter colour-by-fill (≥80 success/≥50 warning/else error) is a clean reusable, consumer-overridable pattern. Build a page as a config-driven shell with a `children` slot so later passes drop in without refactoring it.
- **Settings governance + nav rule:** every Settings surface is admin/role-privilege gated (the RoleSheet privileges matrix IS the control plane); Main-org vs Sub-org governs visibility (sub-org config inherited read-only — Tags `readOnly` is the reference; real enforcement = T-005). Build the CONTENT panel from a frame but keep the CURRENT DS SettingsNav — some frames ship an OLD rail (T-004 closed WONTFIX). AppShell must **key settings content by item id**, else two items whose `render` returns the same component TYPE share one React instance and bleed transient state.

## The autonomous team (how it must run)
- **Standing Process Rule:** EVERY user fix-prompt during any session IS a defect signal and MUST produce three artifacts — (1) a ticket, (2) a defect-log class bump, (3) a retro learning — even for "trivial" one-liners. Defect→gate promotion (SI-4) + memory coherence depend on accurate, complete counting; a skipped trivial fix costs a missed gate + a blind spot.
- **Operating Contract** (docs/AGENT-TEAM-OPERATING-CONTRACT.md): (1) DELEGATE BY DEFAULT — substantial work runs the persona team / review-fix workflow; solo only for trivial edits/answers. (2) RUN TO COMPLETION — no "go/next" nags; yield only when done+verified, blocked, at cap, or a genuine user decision. (3) COLLABORATE via routed verdicts (NOT peer chat — a documented limit), maximised with parallel panels + multi-round review→fix→re-review. (4) VERIFY for real (gates + parity) then LEARN. (5) Ship code + `.spec.md` + update `docs/`. Enforced by UserPromptSubmit + gate hooks (a hook injects context, it doesn't run the loop).
- **The review panel is worth running even when I hold the design context** — 4-persona panels have caught genuine BLOCKERS solo-building missed (drop-on-save/load, assign no-op). But panels also over-normalize (shrank tag chips to the Badge spec, losing Figma parity) — the integrator arbitrates design-parity vs internal-consistency, and the **user-given Figma is the source of truth**. Trace before fixing: a ticket can be stale (T-002 was already fixed — verify by reproduction).
- **Self-improvement is a watchdog** (`scripts/team/self-improve.mjs`, SessionStart): deterministically surfaces DUE actions — defect→gate promotions (defect-log `count>=2` & gate `none`), memory consolidation (learnings >24), persona-note bloat — so adapt/fix is proactive. LEARN = retro + memory + persona-notes injected each session; ADAPT/FIX = watchdog + defect→gate promotion + gates that grow. Honest limit: deterministic detection + loop action, NOT self-modifying code. `retro-append.sh` only appends (re-introduces near-duplicates) — the consolidation trigger catches that drift.

## Product builds & chrome generality
- **Parallel-agent product build works** (ifm-workforce, 16 modules in one loop): 5 frontend-eng agents over a centrally-authored data spine (types + seeds + derive.ts) + an explicit per-agent file contract (shared `worker-detail.tsx` published as a contract others import before it exists) → zero integration conflicts, tsc-clean on first assembly. Diagnose import-time crashes (a salted-id lookup crashed BEFORE console capture → blank page, zero logs) via `import('/src/main.tsx').catch` in eval.
- **Chrome vocabulary MUST be configurable, not baked** (T-016/17/18 → now the G-VOCAB gate): DS app-shell chrome defaults (ReportsHome landing category, live-monitoring fleet labels/`kind` exclusions, module rail) are fleet/asset-specific and break products with other data models (workforce attendance, site presence, generic reports). Pattern: expose config props with BACKWARD-COMPATIBLE defaults (`listColumnLabels?` defaults to `{Vehicle, Activity, Speed}`; `defaultTab='all'` not first-category; hide-scrollbar idiom `[scrollbar-width:none]`+`[-webkit-scrollbar:none]`). G-VOCAB (vocab.mjs) flags a baked fleet word in JSX text / a non-overridable default label but exempts the sanctioned `?? '<word>'` fallback; `// vocab-allow <word> — <reason>` documents an intrinsic case.
- **Workforce-presence monitoring pattern** (reusable recipe): punch-location pins render attendance-derived states (in-zone/late/out-of-zone/missing-punch/checked-out/no-show), NOT geolocation telemetry. Configure `live-monitoring` with `assetType 'default-workforce'` (not `kind:'site'`, which the list excludes by fleet design) + monit data from worker shifts/punches + state derivers from shift+attendance. Reframes "monitoring" from asset tracking to worker attendance.
- **Gate-design meta-lessons** (from building G-VOCAB + G-HYDRATION as SI-4 promotions): (1) a chrome-vocab scan MUST detect+exempt the sanctioned overridable fallback `?? '<word>'`, else it flags the very config-default pattern it exists to encourage; (2) a JSX-text regex must be single-line (`[^<>{}\n]`) or a `>` in code (`=>`) swallows string literals on later lines (both caught in red-check — always red-check). (3) When a defect class has multiple root causes, gate only the slice with a clean zero-false-positive static signature and route the rest to the review-fix checklist — a narrow gate that runs every edit beats a broad one that false-positives (G-VOCAB left `kind`-branching, G-HYDRATION left seed-omits-row-field/composite-corruption, to the checklist). (4) Finishing an interrupted run: UPDATE the divergent artifact's references in place (the user may rescope/rename it — `domain-vocab.mjs`→`vocab.mjs`) rather than appending near-duplicates; protects the just-consolidated memory.
- Command-surface pattern (T-021, ifm-workforce 'Workforce Pulse'): when users say 'dashboard' but mean OPERATE (act on live signals), build ONE DispatcherCockpit-shell surface, not several passive KPI pages — (1) role switcher (Management/Line Manager/HR) swaps the KpiMetricCard set AND filters a unified action queue; (2) 'live' on static demo data = a simulated clock ticking from the demo 'now' that reveals deterministic punch/eventstreams and re-derives every KPI/panel per tick (no Math.random); (3) every queue card carries real actions that mutate state + toast a concrete outcome + clear; (4) domain vocabulary stays domain-true end to end (HR product ⇒ no fleet words — G-VOCAB guards the DS side). Absorb sibling dashboards (Capacity) as status panels + queue signals.
- T-021 follow-up (user fix-prompt): do NOT invent per-role views/RBAC personas in a single-login admin demo unless the user asks — the ifm-workforce Workforce Pulse role switcher (Management/Line Manager/HR) was removed same-day; the admin surface shows the UNION (all KPIs grouped presence→risk→business→people + the full unfiltered action queue). Persona-scoped views are a real-product concern gated on real auth, not a demo default.
- DispatcherCockpit gained two config slots (T-021 follow-ups, user-driven): filterSlot (FUNCTIONAL filter fields rendered in the cockpit's own filter row — products whose filters drive data shouldn't bolt a separate bar above the shell) and kpiHeader (node above the KPI grid — e.g. a role-tab strip used as a KPI LENS). - T-033a (user escalation, 'ignored-existing-ds-component' count 5): search inputs are NEVER a bare `<Input>` — the DS search field is one fixed composition everywhere: relative wrapper + `SearchMd` icon absolutely positioned left (pointer-events-none, text-muted-foreground) + `pl-8` input + placeholder **"Search anything here"**. - THE 10-TICKET WAVE (T-041..T-051 + audit, one day, ~10 parallel agents): the pattern that worked — (1) DISJOINT FILE CONTRACTS per agent with an explicit "your files ONLY / frozen files" list; (2) shared foundations FROZEN for the wave (store.ts, types.ts, derive.ts) with applyDelta/custom-bucket as the escape hatch — zero merge conflicts across ~40 touched files; (3) laws pasted VERBATIM into every contract (agents don't inherit chat context); (4) conductor commits per ticket AFTER reading the agent's screenshots himself — two agents' honest self-flags (leftover fleet copy, unmirrored vendor patch) were caught this way; (5) cross-agent handoffs as DATA contracts (workers.ts relations, scansFor, approvedTotalsFor) with a documented fallback if the producer hasn't landed. Pitfalls hit: staging a SHARED file (App.tsx) mid-wave swept another agent's in-flight edits into a mislabeled commit — always diff-check before `git add` on shared files; concurrent agents saturate the machine (tsc/shoot timeouts — scope tsc greps per-file, retry shoots); an API-session-limit kill mid-agent is recoverable via SendMessage resume-from-transcript with the working tree intact (check tsc first).
- COHERENCE = ONE DERIVATION, MANY READERS (T-038 p2): when two surfaces disagree (Pulse hiring-gap vs Projects, payroll hours vs timesheet hours, KPI tile vs its own raw sheet), the fix is never a display patch — export the ONE derivation from the owning module/data file and make every reader call it (openDemandTotal, timeInZoneMin-based hours, filtered-pool KPIs). Also: module-scope `const X = build()` computed at import time silently freezes a "live" surface — Pulse read import-time snapshots of leave/workers/inventory and never reflected store mutations until wired through useStore.
- DS Z-LAYER TOKENS (T-052): floating primitives must stack via shared constants (z-layers.ts: sheet 1200 < dialog 1300 < floating 1320) applied as inline style in the primitives themselves — Tailwind arbitrary-value classes can't take a JS constant and twMerge order isn't guaranteed. Never fix layering per-instance; three hacks accumulated in one day before the promotion rule forced the real fix.
- INTAKE COMPLETENESS (conductor process defect, caught by user-ordered re-analysis): a client walkthrough message with 14 module sections yielded 13 tickets — the Shifts section was silently dropped while batching. RULE: when ticketing a multi-section punch list, COUNT the sections, count the tickets, and reconcile 1:1 (a section may merge into another ticket only with an explicit pointer). Re-read the SOURCE message during the check, not your own summary of it — the summary inherits the omission. The user's standing bar: agents run "full mode", the DS is the core AND the bounds, Figma refs are parity targets, and nothing ships half-baked — every dispatch carries the laws verbatim, every result is screenshot-verified by the conductor, QA passes route re-fixes before commit.
- T-039/T-040 (geo at scale): (1) NAME LABELS on thousands of map entities must be a native MapLibre SYMBOL LAYER gated past the cluster radius — per-entity DOM markers freeze the map at 5k+ (measured); (2) selection fly-to must preserve the CURRENT zoom (flyTo falls back to map.getZoom(), never a hardcoded zoom); (3) after a create-on-map flow, fitTo the NEW geometry — fitToContent over the whole dataset makes the creation imperceptible; (4) two toolbar glyphs that look alike (Maximize02 vs Expand) read as a duplicate control — pick visually distinct icons per function; (5) audit references can be wrong too: before "fixing" coordinates against a prompt-supplied anchor, check whether the on-map placement was already verified — the anchor may be the error.
- T-036 (INP, new class 'heavy-mount-in-event-handler'): when an event handler's setState swaps in a heavy surface — the auth→AppShell mount, a module-scale view, a sheet with a big DataTable — React renders it in the urgent lane and the click's next paint waits for the WHOLE render (537ms INP on Login). Wrap the swap in `React.startTransition(...)` (interaction paints first, mount renders non-blocking); keep the cheap urgent bits (validation errors, pressed state) outside the transition. Login → full-app mounts are the canonical instance in every FAMS demo product.
- T-031 (kit-lift + map): 'zones' and 'pois' are now first-class DS module types (ZonesView/PoisView + module-registry entries) — products configure them, never re-compose geo hybrids. MapLibre canvas can't parse `var(--x)`: MapView now resolves token colors via a hex fast-path + getComputedStyle before paint (2nd 'token-color-in-non-css-renderer' instance — the checklist line works). - T-034 (Settings standard, 'ignored-existing-ds-component' count 6): a product's Settings gear surface is NOT a place for bespoke pages — it mirrors the DS settings block (blocks/settings/settings.block.tsx): Platform Settings (Tags & Categories · Roles · Application Mgmt · Event Config · Entity Config · Pipeline Config · Preferences · Module Mgmt · Subscriptions · Appearance · Billing) + Organization Settings (User Accounts · Org Settings · Sub-Org readOnly), reseeded with the product's own domain. Domain org-config (clock-in channels, compliance thresholds) is folded INTO the DS-managed surfaces — toggles/numbers into Preferences sections, event-ish rules into Event Configuration — never standalone one-off pages; backend-identity config (WPS employer/bank) and dev tools (reset demo data) don't belong in front-end Settings at all. User Accounts seeds ADMIN/back-office staff, not the operational workforce entities.
- T-035a (user law, class 'status-color-collision'): NEVER give two statuses in the same set the same color — and know the palette: `--chart-4` (#12B76A) is visually the SAME green as `--status-success`, so a stage set using both reads as one status (Payroll Approved/Paid, Lifecycle Transfer-Promotion/Permanent — both hit it). When assigning stage colors, treat chart-4 and status-success as one color; after any fix, sweep EVERY `STAGES` array in the product, not just the reported one (T-023 lesson).
- T-035b (FAMS module-toolbar standard, 'ignored-existing-ds-component' count 7): search field · filter fields · primary action live on ONE toolbar row, and a filter field's label lives INSIDE the field as its value text ("All Client Types", "All Stages" — DS Select w/ SelectValue), NEVER as an external `<label>` beside it. If the DS surface owns the toolbar but lacks a slot, extend it DS-side with backward-compatible props (ContractManagement gained `filterSlot` + `createLabel`, mirroring the DispatcherCockpit filterSlot precedent) instead of bolting a product chrome row above the component.
- T-033b (new class 'rail-nav-duplicated-as-action'): never render a header/toolbar action whose only behavior is navigating to another module on the rail — the rail IS the nav, and duplicating it as chrome (Pulse's 'Open live map' → Live Monitoring) is noise the user reads as broken UX. Header actions must act in-place: mutate state, open a sheet, trigger a job. Cross-module deep-links are sanctioned only from DATA (a row/card that opens its owning record), never as standing chrome.

- T-053 (module IA law): feedback about a module's CONTENT is never a mandate to restructure the MODULE (name/rail slot/tabs/default view) — the T-046 agent turned 'fix the Visual timesheet report' into a module rename+demotion and the client caught it ('properly think before breaking a module'). When a new surface needs a home, PROPOSE the IA change in the report; the conductor/user decides. Related consolidation pattern: overlapping time surfaces (scheduling/timesheet/attendance) belong in ONE module as views — re-home surfaces as-is (export the view from its owning file; a thin composition module switches on ctx.activeTab.id); dashboard-type tabs get NO shell toolbar (TOOLBAR_TYPES = entity/pipeline only) so a re-homed entity surface must bring its own.

- T-056 (formatting prevents FALSE data alarms): a missing thousand-separator made 56,759.9h read as '567,599.9h' and got flagged as an implausible-magnitude data bug — display hygiene is also data-credibility hygiene. ONE shared formatter module (data/format.ts: nf + aedCompact) is the fix pattern, never per-file ad-hoc `/1000).toFixed(0)+'k'` math; the same fact must render identically on every surface (25.6M vs 25608k for one payroll run was the client-visible failure).

- T-057 (chart + shell hardening): Recharts draws NO path for a single 100% Pie slice when paddingAngle is set — any donut whose data can collapse to one category needs the single-datum SVG-circle fallback (now in the DS DonutChart; consumers that .filter(v>0) their slices are the trigger). And the AppShell now has a per-module error boundary (keyed by module id, in-place Retry) — before it, ANY runtime error in any module white-screened the entire app; a 1,200-line cockpit module with live simulation was one bad render away from killing a client demo.

- T-058 (two subtle chart/threshold classes): (1) EXACT-EQUALITY thresholds die at scale — 'fully covered' = present===scheduled is unreachable across 8k workers; status bands must be %% ranges (>=95%% full, <85%% gap). (2) In cumulative breakdown bars, ZERO-VALUE segments must be filtered BEFORE the cumulative-width loop — a stable sort let a 0-value error segment paint at full width on top of the real amber one (an 'all-red bar' for all-partial data). Also: the SESSION-LIMIT recovery pattern is now proven twice — on agent failure, check tree+tsc first, then SendMessage-resume the same agent with a precise 'already landed' inventory; agents edit the real tree, so failures lose nothing.

- T-062 (the 'missing' search icons were a PAINT bug): the DS Input primitive renders a POSITIONED inner wrapper — any icon absolutely-positioned OUTSIDE it (the hand-wrapped search pattern) paints UNDER the input wherever the input bg is opaque (equal z → DOM order). The icons were present in the DOM the whole time; DOM presence checks pass while pixels fail. Fix classwide with z-10 on the icon, and the FORWARD LAW: use Input's own `leadingIcon` prop — icons inside the wrapper sit above the non-positioned <input> by construction. Verification lesson: a claim about VISIBILITY needs a pixel (screenshot), not a DOM query — and elementFromPoint can't test pointer-events-none elements.

- T-064 (sheet-over-sheet lifecycle): stacking a module-owned Radix Sheet under the shell DetailSheet needs BOTH reverts handled on detail close — (1) your own state (the shell now exposes ModuleRenderContext.detailOpenCount; collapse expanded geometry when it hits 0), and (2) interactivity: Radix does NOT restore pointer-events on a still-open background modal after the one above it closes — reassert pointer-events:auto on your SheetContent (safe while stacked; the top modal's overlay intercepts). Verify interaction bugs through the FULL cycle (open→drill→stack→close→click again), not just the happy path.

## 2026-07-14 — T-065 wave retro (16 fixers + 2-iteration re-review, ifm-workforce)
- **Mirror discipline:** before any DS→vendor (or reverse) overwrite, diff against `git show HEAD:` of the target — unexplained DELETIONS are a stop signal. Root cause class: a botched `$var` shell write had left the DS source stale (`app-shell$f`), so a *correct* mirror step destroyed shipped code. Truth = whichever side shipped+verified last.
- **Truncation is not a layout fix.** `truncate` + title tooltip on a clipped value passes a single-record screenshot but fails the class (tooltips don't exist on projectors/touch; date ranges must never hide their tail). Fix the LAYOUT (label shrinks to content, long values wrap) and verify on MULTIPLE records — the re-review swept records the fixer's proof didn't.
- **Locale-formatted numerics:** `<input type="number">` renders the OS locale's decimal separator; bare `toLocaleString()` follows the OS locale. Three same-day client catches ("3,5" / "60,4" / "AED 100.000"). Law: `lang="en-US"` on number inputs; only `toLocaleString('en-US')` or the shared nf/aed formatters.
- **Parallel fixer waves work on disjoint FILE contracts** — 9 concurrent fixers, zero lost edits — but: (a) global `git stash` is FORBIDDEN mid-wave (targeted `git stash push -- <own-files>` only; two fixers risked others' work); (b) whole-project tsc is flaky while peers save — isolate your diff via targeted stash before blaming; (c) a scope-add mid-flight (SendMessage) beats a queued colliding fixer when the same file is owned.
- **Long-running Vite dev servers go stale** (watcher death): served a pre-edit transform even after full reload — the QA "STREAM is not defined" intermittency was this too. If `fetch('/src/…')` disagrees with disk, restart the server; verify served == disk before pixel-verifying an edit.
- **A same-tick day-click + Apply-click in scripted React tests reads pre-update state** ("Custom" label) — yield (setTimeout) between interactions before declaring a product bug.
- **The post-fix ui-designer re-review over RESULTS (not diffs) is load-bearing:** it caught 8 real defects after 16 green fixer reports — including a DS-internal ignored-DS-component (SchemaForm rendering native date inputs) and the truncation-class survival. Keep it mandatory before any wave commit.
