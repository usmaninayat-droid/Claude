# Decisions (ADR-style) — what we chose and why

- 2026-06: Cards render dynamically by field type (not per-use-case React). Reason: coherence + one card serves every pipeline.
- 2026-06: Detail uses TaskDetail + config-driven right-panel tabs. Reason: match demos/Figma; stay config-driven.
- 2026-06: Progress supports stage-derived (StageProgress) + numeric. Reason: every pipeline gets progress with zero extra data.

- 2026-07: RoleSheet/RolesManagement triage — round-trip contract is the blocker (RoleRow must carry appIds/privileges/description so edit pre-populates + save persists all 4 draft fields; consumer derives `access` from exported DEFAULT_APPS, not an `id.toUpperCase()` hack). Reason: same drop-on-save class as CategorySheet; single source of truth = law #4.
- 2026-07: a11y "44×44 touch target" tickets on the roles kebab, role pill, and privilege matrix are DEFERRED — 44px is WCAG 2.5.5 (AAA/mobile), not the AA 2.5.8 (24px) minimum; forcing it blows up desktop table density + the privilege matrix and breaks Figma parity. Integrator rule (learnings): panels find real a11y bugs (missing focus rings — kept) but the integrator arbitrates design-parity vs over-normalization. On-grid consistency fix (PrivBox size-[18px] → size-4) is taken instead.

- 2026-07: **Settings model (applies to EVERY Settings surface).** (1) Audience = Admin / C-level / managerial only; every Settings page is **role + privilege gated** — the RoleSheet privileges matrix (module × create/view/edit/delete) + Applications step ARE the control plane that decides who sees/edits what. (2) **Org scope:** a setting's visibility/editability depends on **Main-Organization vs Sub-Organization** role — org-level config is inherited **read-only** in a sub-org (reference pattern: the sub-org Tags view = same component in `readOnly` + org-context header); real enforcement needs the settings-level shared store (T-005). (3) **Ignore old nav in the Figma frames** — some Settings frames ship an OLDER SettingsNav; build the CONTENT panel from the frame but keep the **current DS SettingsNav** (blocks/settings sections), never copy the frame's rail. Consequence: T-004 (frame nav labels differ) → **wontfix** (frame nav is the old one, intentionally not matched).
