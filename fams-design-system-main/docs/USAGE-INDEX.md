> **How to keep this current:**
> 1. When you port a new component or change an existing one's `@usage-v5`
>    block, re-run the extraction (grep every non-test `.tsx` under the five
>    layer directories for a leading `/** … @usage-v5 … */` block) and update
>    this file's matching row/section by hand — there is no build step that
>    regenerates it automatically yet.
> 2. If a component's `@usage-v5` block changes wording, this file should
>    quote the new wording, not the old.
> 3. If you add `@usage-v5` to a component that currently has none (see the
>    coverage gap list at the bottom), add a new row rather than leaving it
>    undocumented here.
> 4. Do not paraphrase away specifics (file paths, occurrence counts) — those
>    are the whole point of the annotation; keep this index as factual as the
>    source comment.

## Coverage gap — components with no `@usage-v5` block yet

55 components (see per-layer lists above) currently have no `@usage-v5`
annotation in source. This index cannot state what v5 pattern they replace
without fabricating it — that information has to be added to each
component's own JSDoc first, then reflected here. Full list:

- **Primitives (14):** `Button`, `Calendar`, `Checkbox`, `Dialog`, `DropdownMenu`, `Input`, `Label`, `Popover`, `Select`, `Switch`, `Tabs`, `Textarea`, `Toast`, `Tooltip`
- **Layout (4):** `FormGrid`, `FormSection`, `Stack`, `Toolbar`
- **Composites (24):** `AreaChart`, `BarChart`, `Card`, `ChartContainer`, `ColumnCustomizer`, `Combobox`, `CompareBars`, `DataTable`, `DataTableColumnsMenu`, `DataTablePagination`, `DataTableSummaryRow`, `DataTableVirtualBody`, `DonutChart`, `FileUploader`, `FilterPanel`, `HeatmapChart`, `LineChart`, `ListRow`, `Logo`, `Skeleton`, `Sparkline`, `TableCellRenderers`, `TagChipList`, `TagPicker`
- **Shells (8):** `AppShell`, `HybridView`, `ListView`, `ModuleRail`, `PageHeader`, `ProfileLayout`, `SideNav`, `TopNav`
- **Domain (5):** `MapChip`, `MapContainer`, `MapControls`, `VehicleMarker`, `VehiclePopupCard`

Several of these are exactly the components a v5 engineer would look up
first (`Button`, `Input`, `Dialog`, `Select`, `Tabs`, `AppShell`, `TopNav`,
`SideNav`, the whole map domain) — closing this gap should be prioritized
over adding new components.
