Selection UX — three directions

All three are opt-in (no permanent checkbox column) and carry the same guardrails. They differ in how you turn selection on. Hover a row, tick a box, and watch each one. Pick the feel you want and I'll make it the single canonical pattern.

1

Hover-reveal — no button at all Recommended

There is no Select/Cancel button. Checkboxes are invisible until you hover a row, then fade in. Ticking one enters selection mode implicitly; the action bar appears. This is the Linear / Notion / Gmail pattern — zero chrome for the 90% who never bulk-edit, instant for those who do. Touch devices get a long-press fallback (not shown).

2

Toolbar morph — Gmail style

A small Select icon-button sits in the toolbar. Clicking it slides the entire toolbar into a dedicated blue selection toolbar (count + actions + Done), and the checkbox column appears. The whole header changing colour is the strongest possible "you are in a different mode" signal — impossible to miss, no floating element.

3

Refined floating bar — dark command pill

Closest to your current build, but elevated. A Select icon-button reveals the checkboxes, and a single dark, rounded command pill floats up from the bottom with the count and actions. Feels like a focused mini-app while active; the ✕ dismisses it. Good if you want the table itself to stay visually untouched.

4

Toggle switch — persistent on/off

A labelled Bulk edit switch in the toolbar. Flip it on and the checkbox column + action bar appear; the switch stays visibly "on" the whole time, so the mode is legible even when nothing is selected yet. The label names the mode's purpose (tags, colour, delete) rather than the verb "Select". Keyboard-accessible (role="switch", Space/Enter). Caveat: switches usually read as a persistent setting rather than a transient task — see if it feels right here.
